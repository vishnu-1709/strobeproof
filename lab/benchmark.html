Benchmark

Two parts. First, how Strobeproof compares with existing tools, using only what each tool's public store listing says. Second, Strobeproof's own measured result on the known-answer cases: for every failing case, did above-threshold flashing reach the screen? The method is below so anyone can repeat it.

Method

  1. Clips: every suite case except 14 (variable frame rate can't be stored as a constant-rate file) and 15 (Strobeproof's own Calm Mode), encoded as constant-frame-rate MP4 by tools/make-bench.mjs straight from the synthetic frames. Each encoded clip is re-checked in the Lab and gives the locked answer (e2e/bench-clips.spec.js).
  2. Strobeproof: automated in headless Edge with the extension loaded. Each clip plays as a normal video at 160×90 px in a 160 px-wide window, which is exactly the 1024×576 reference display. Every presented frame records whether the clip was at normal brightness (e2e/bench-self.spec.js). No human watches; nothing is recorded.
  3. Other tools were not run through the benchmark. The comparison above uses only their public store listings, checked on the date shown; "?" means the listing doesn't say.

Known limit of the live path: at exactly 3 flashes per second (cases 3a–3d) Strobeproof can err on the safe side when the browser skips frames, because each change is seen up to a frame late. GIFs and pre-scanned videos are decoded frame by frame and are exact.

Strobeproof reduces exposure; it is not a medical device.
